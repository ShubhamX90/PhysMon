### J14.9-001 · 2026-10-17 · decision
kind: decision
**What:** Extend the pilot runner so that every decoy-defined record also stores the decoy string's log-probability under the no-cue prompt of the same instantiation (`alternative_scores.decoy_under_anchor_prompt`), and let the template run one job per dtype
(`DTYPES`, default `bfloat16`). The new job repeats the full committed plan (211 jobs per model) in bfloat16 and float32.
**Why:** J14.8-003: (a) R_alt differences between cells compare different strings, so a cue effect needs the change in the same decoy's score against its no-cue score; the proper answer-competition shift is
R_alt(cue prompt) minus R_alt(no-cue prompt) = delta gold minus delta decoy; (b) no cue effect of a fraction of a nat can be read without a dtype noise floor (P1.7).
**Alternatives considered:** a separate scoring-only script (rejected: the runner already has the model loading, the contract and the record format, and a second code path would need its own tests); a repeat pass in bfloat16 only (rejected: greedy decoding and a deterministic forward pass reproduce
the same numbers, so it would measure nothing; the dtype change is the variation that exists).
**Tests [V]:** `test_pilot_s147.py` 11 passed (a new test recomputes the anchor-prompt decoy score independently with the tiny model and checks the stored value, that cells without a decoy store none, and that the stored value differs from the cue-prompt score).
**Not changed:** the correctness rule, the plan, the wrapper, and the structures.
