### J14.11-001 · 2026-10-18 · decision
kind: decision
**What:** Register every Stage 14 result and material directory with the SHA-256 of each file, and keep a separate register of the Slurm jobs of this task, including failed and cancelled ones.
**Why:** Stage 14.0 created the claim ledger but nothing tied a result to bytes, so a later edit to a raw-record file could not be detected. P0.1 asks for an immutable registry. The job register keeps the failed and cancelled attempts on record next to their causes in the journal (AGENTS.md: preserve failed and partial evidence).
**Design:** `--write` appends new artifacts and never rewrites an entry; it refuses if a registered artifact has changed. `--verify` reports changed, removed, unregistered and unregistered-directory cases and exits non-zero; an empty register is an error. A correction is a new attempt directory, not an edit. Every entry has `paper_eligible: false`
and the evidence class its own summary states (otherwise "derived or preparatory; no run authority claimed"); the register does not make a result authoritative.
`--add-jobs` reads `sacct` (read-only) and links the output directories that carry the job id in their name (the smoke job 399217 is linked explicitly).
**Tests [V]:** `test_artifact_register.py`, 7 passed, on a synthetic root (hash and metadata capture; verify catches change, removal and addition; unregistered directories and an empty register are errors; append-only writing and refusal on change; the job register keeps failed and cancelled jobs; explicit link; exit codes).

### J14.11-004 · 2026-10-18 · correction
kind: correction
**What I got wrong [V]:** while job 401357 was still running I ran `register_stage14_artifacts.py --write`, which registered its output directory with the hash of a file that was still growing, and I committed that entry. A registry entry of an incomplete directory would fail verification as soon as the job wrote another record.
**Fix:** the entry was removed from `artifact_register.jsonl` (it was an error, not evidence; the register is append-only for valid entries) and the tool now refuses to register, and does not expect to find registered, the output directory of a job that `squeue` still shows (the job id is read from the `attempt_<jobid>_` directory name, 5 to 7 digits so that dates are not mistaken for job ids). An unreadable queue is an error, not "nothing is running". Two new tests cover the skip and the job-id parsing; 9 tests pass. The directory is registered after the job leaves the queue.
