kind: decision
**What:** Prepare the pilot completely, but stop at the submission boundary.
**Why:** The user asked for "the full stage 14". The pilot is the first stage that needs a GPU. `AGENTS.md`, the Sharanga skill
and `CLAUDE.md` require explicit authorization in the current task for Slurm submission and GPU work, and that authorization

on a shared account is not reversible in the way a commit is); running the pilot on CPU (rejected: a 7B to 8B model on CPU
is not a faithful stack for the scoring contract and would spend shared CPU for an answer that is not decision-relevant).

### J14.7-002 · 2026-10-16 · decision
kind: decision
**What:** A new scorer, `physmon.scoring.v2_scorer`, rather than editing the legacy scripts.
**Why:** The Stage 14.3 audit found the legacy scoring path does not satisfy the contract. The new module tokenizes with
`add_special_tokens=False` after applying the chat template (so BOS appears exactly once), derives the answer span from the
contract (`answer_span`), and refuses with a recorded status rather than a number when the separate and joint tokenizations
differ (`BOUNDARY_MISMATCH`) or a second BOS is present (`DUPLICATE_SPECIAL_TOKEN`).
**Evidence [V]:** tests build the pair with the real Qwen and Llama tokenizers and score it with a tiny random model, checking
that the scored span is exactly the contract span; planted boundary and duplicate-BOS cases are reported as statuses.
