### J14.19-001 · 2026-10-26 · decision
kind: decision
**What:** On 2026-10-26 the user instructed: build a dataset of at least 200 samples, each with a gold trace that contains not only the gold answer but the perfect approach to solving the problem; use thinking models that can answer correctly, and then measure sensitivity to distractors; "override the physicist checking part"; deploy specialised agents (one for classical mechanics, one for quantum, and so on) that make the problems, add a verifier agent, and include a gold thinking trace that is a step-by-step solving technique and not a model's text.
**Decisions taken [I]:**
1. **The human physicist review is replaced by agent verification, by the user's instruction, and the category says so.** Every new item carries the framework's `UNREVIEWED` admission category (the certifier's meaning: no human expert has reviewed it) plus an `agent_verification` record: author agent, blind solver agent, plan reviewer agent, and the outcome. No document of this stage may call these items expert-reviewed, physicist-confirmed or validated by experts, and the Phase-I and v2 claims about independent review stay NOT_EVALUATED. The user's earlier one-reviewer walkthrough of S01 to S20 is unchanged; S21 to S30 had none, and this stage's agent checks stand in for it by the user's decision.
2. **A gold trace is generated from the typed graph, not written as free text.** The author of a structure supplies, for each computed node, the NAMED principle that produces it and why it applies (a `Plan`, with an approach sentence and a sanity check); `render_trace` evaluates the givens, the symbolic relation, the numeric substitution, the result and the unit from the graph, so the trace's numbers cannot disagree with the graph, and its last value is checked against the structure's independent solver. The trace is therefore a solving technique, not text produced by a model while answering.
3. **Specialised domain agents** author new structures in their own module (`lib_<domain>.py`: structures, plans, difficulty labels): classical mechanics, electromagnetism and circuits, thermodynamics, optics and waves, quantum mechanics, modern physics (relativity, nuclear), fluids and continuum. Each also writes plans for the existing structures of its domain (S01 to S30). New structures need at least four numeric instantiations each, so that about 50 new structures give about 200 samples and the 30 existing ones add 60.
4. **A verification chain per domain, all by different agents from the author:** a blind solver that sees only the problem text and the answer unit (no gold, no trace); a plan reviewer that runs the numeric comparison, derives disagreements independently, checks every principle and wording in the rendered trace, and rules on the problem's well-posedness; one repair round by an author agent; and a second blind check of every repaired item.
**Limits stated before any item exists [I]:** agent-written physics can be wrong in ways that agent checks share (the same model family, the same blind spots); numeric agreement of the gold with an independent blind solve is evidence of arithmetic and formula correctness, not of wording clarity or modelling choices; difficulty labels are the author agent's judgement; thirty to eighty structures are still clusters, so the effective sample size for any structure-level statement is the number of structures, not the number of instantiations.
**Scope:** CPU and agents only; no GPU job, no download, no Slurm action in this step. The runs of reasoning models on the dataset come after it exists and need the user's acceptance of each exact command.

### J14.19-002 · 2026-10-26 · result
kind: result
**Build [V]:** the framework (units, trace renderer, plan validator, author check tool, blind-verification tool) was committed first (`c57a193`); then one workflow of 36 agents (7 authors, 7 blind solvers, 7 plan reviewers, 5 repairs, 5 second blind solves, 5 second reviews; about 2.7 million tokens, 20 minutes) produced seven modules `src/physmon/benchmark/v2/lib_{mechanics,electromagnetism,thermodynamics,optics,quantum,modern,fluids}.py` with 50 new structures (ids S31 to S38, S41 to S48, S51 to S57, S61 to S67, S71 to S79, S81 to S86, S91 to S95), their gold plans, and plans for the 30 existing structures S01 to S30. Authors were instructed to write only their own module and scratch files; the blind solvers were instructed not to read the repository (an instruction, not an enforced sandbox).
**Verification outcome [V]:** reviewers accepted 74 of 80 structures at the first pass (all with blind-solver agreement on every instantiation; `blind_match` true everywhere) and asked for fixes for 6: S37 (the question did not say the answer unit), S48 (a node was labelled with the wrong unit `rad/s^2`), S73 (three of four transitions in an infinite well are dipole-forbidden for an emitting electron), S84 (a relevant edit produced a special ratio), S91 (a plan sentence said the tappings are at the same height, which is not what makes the result independent of height), S95 (the plan principle named the wrong law for the small piston). Five were repaired by an author agent and accepted by a second blind solve and review. S73 was repaired (new instantiations with odd changes in n), but the second reviewer asked for a wording fix (a missing full stop and a run-on assumption); the workflow's rule marked it excluded; I made the one-sentence wording fix myself, and a fresh blind solver and reviewer (third round) accepted it: all four gold values reproduced by the blind solver, repair complete. Final status: 74 accepted, 6 accepted after repair, 0 excluded (`data/v2/dataset/verification_status.json`, with every reviewer issue).
**My independent check [V]:** I re-ran the author check tool on all seven modules myself, with every other new module as an overlap reference: 50 of 50 new structures SOLVER_CERTIFIED, no program equal to a v1 template, to an existing structure or to a structure of another domain module, at least four instantiations each, every plan valid, mutation harness 0 missed and 0 wrongly rejected; failures=0 in each domain. I read the rendered traces of the quantum module and hand-checked the first instantiation of the photoelectric, de Broglie, infinite-well, Bohr-recoil and Compton problems: all correct. The trace text printed a doubled full stop after a principle that already ended with one; I fixed the renderer (text only).
**Caveats the reviewers and I recorded [I]:** blind solvers raised 13 concerns, mostly missing conversion constants (1 u in MeV or kg is not given in some prompts), an assumed reversible compression, and a vertical field on an inclined rail; reviewers accepted these as standard assumptions. `known_issues.json` lists them. The 50 new structures' physics was authored and verified by agents of the same model family; a shared blind spot would pass every check here.

### J14.19-004 · 2026-10-26 · decision
kind: decision
**What:** A thinking-model runner, `scripts/v2/s164_thinking_run.py`, for the next step (nothing has been run on a GPU). It takes the dataset (`--source base`, the no-cue problems) or its distractor cells (`--source cells`, optionally restricted to given structure:instance keys such as the base-correct anchors), and runs one model with vendor-recommended sampling (temperature 0.6, top-p 0.95; greedy decoding loops on thinking models), batched with left padding, `--n-samples` samples per problem so that a problem solved in every sample can be told from one solved by luck, a token budget (default 8,192), the Stage 14.13 final-line contract in the user turn, and parsing of the text after the last `</think>`. Thinking that never closes at the limit is TRUNCATED; a final-line phrase inside the thinking is never an answer; log-probability fields are null. Raw records are flushed after every batch.
**Bug found by the tests [V]:** Llama's tokenizer has no padding token, so the first batched call raised an error; fixed (`pad_token = eos_token`). Two of my own test assertions were wrong and were corrected (the Llama manifest does record a revision). 6 tests pass on a tiny random Llama on CPU: parser cases, job construction, refusal without an authorization reference, complete records with unique ids, greedy mode, time budget, used-directory refusal.
**Model registered:** `qwen3_thinking` (Qwen/Qwen3-32B, already on scratch, no revision manifest). `deepseek_reasoning` (DeepSeek-R1-Distill-Qwen-32B) already existed.
**Proposed run design, for the user's acceptance before any submission [I]:** (1) a speed test of 20 problems on one H100 per model to measure tokens per second and thinking length (no speed has been measured for 32B on this stack; a rough guess is 20 to 25 tokens per second per sequence); (2) the 260 no-cue problems with 4 samples each for the better model, batch size set from the speed test; (3) the problems answered correctly in every sample become the anchors; (4) the 10 distractor cells on the anchors with the same sampling and 4 samples; flips are compared with the no-cue resampling noise. Estimated GPU time is unknown until step 1.
**Not done:** no GPU job, no download, no Slurm action. Each submission needs the user's acceptance of the exact command and a live preflight.
