### J14.8-003 · 2026-10-17 · decision
kind: decision
**What:** Treat the pilot as a design diagnostic, not a result, and record four design gaps it exposes; none of the cue contrasts above is to be interpreted or cited.
1. **Correctness floor:** both models are about 1% to 3% correct under `answer_line` (J14.7-023), so C_gen is not estimable and base-correct conditioning has no support.
2. **No noise floor:** no repeat or dtype pass exists, so no cue effect of a fraction of a nat can be read against presentation noise (P1.7); bf16 log-probability noise could be of that size.
3. **Decoy not anchor-matched:** R_alt needs the same decoy string scored under the no-cue prompt, so that the cue effect is the change in the decoy's log-probability and the gold's, not a difference between two different strings.
4. **Assay response inconclusive:** the relevant edit is not followed accurately.
**Next stage (proposed, Stage 14.9):** a GPU pass that (a) also scores each decoy string under the same instantiation's no-cue prompt, and (b) repeats the full pilot in float32 next to bfloat16 to measure dtype noise on every gold log-probability. Longer term (X03, wrapper multiverse): a reasoning-allowed wrapper, or structures a 7 to 8 B model can solve, to obtain base-correct anchors.
