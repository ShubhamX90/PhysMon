### J14.13-001 · 2026-10-18 · decision
kind: decision
**What:** Add a separate reasoning-allowed contract (`reasoning-v1`: "work step by step, then write `Final answer: [value] [unit]` on the last line") with its own fingerprint, and a runner that grades only the generated final line, on the same committed pilot plan (the 211 `answer_line` jobs per model, so the same cells and gold values).
**Why:** both models are correct on 1% to 3% of records under the no-reasoning answer line (J14.7-023), so the correctness-transition endpoint cannot be estimated and base-correct conditioning has no support (Stage 14.8 gap 1). The user asked for this fix.
**Why a separate contract, not a new wrapper in the Stage 14.3 contract [V]:** a new wrapper changes the frozen contract fingerprint (`bb6bbec4...`), which every earlier plan and record carries and every plan check compares against. The new contract has its own version and fingerprint; `test_reasoning_s152.py` asserts the Stage 14.3 fingerprint is unchanged.
**Design choices:** greedy decoding, 512 new tokens, bfloat16, seed 42; the parser takes the last `Final answer:` line that stands on its own line; several final lines with different answers are MULTIPLE_CANDIDATES; a generation cut by the token limit with no final line is TRUNCATED, an outcome and never a wrong answer; the declared correctness rule (protocol 4b) applies unchanged.
No log-probability is defined after a model's own reasoning, so the record fields are null (NOT_EVALUATED). The runner writes records one by one and supports `--time-budget-s`, so a stopped job leaves valid partial evidence and the summary counts what was not run.
**Alternatives considered:** easier structures (kept as a separate item: it needs new certified structures); batched generation (rejected for now: a second code path to test, and unbatched cost is acceptable); a teacher-forced score of the gold final line after the model's own reasoning (rejected: its meaning is unclear).
**Tests [V]:** `test_reasoning_s152.py`, 12 passed: parser (value, unit, printed precision, markdown, repeated and conflicting final lines, truncation, mid-line phrase), correctness rule, contract fingerprints, runner on a tiny random model (refusals, complete records with null log-probabilities, TRUNCATED as an outcome, time budget, used directory), counted generation.

### J14.13-002 · 2026-10-18 · decision
kind: decision
**Frozen analysis, decided before the run:**
1. Eligibility strata with denominators per model (B2.4): all valid records; parseable (PARSED); base-correct no-cue anchors (of 20 instantiations).
2. **Gate for the correctness endpoint:** if fewer than 8 of the 20 no-cue anchors of a model are correct, the correctness-transition endpoint is NOT_EVALUATED for that model and the floor is reported as persisting.
3. If the gate is met: among base-correct instantiations, the share of each cue cell that is wrong (a correct-to-wrong flip), by structure, with the cluster bootstrap over structures that have at least one base-correct instantiation; the reverse transition (wrong anchor, correct cue cell) is reported as the chance reading.
4. Copy rate of the cue numeral in the final answer per cell (Wilson interval); TRUNCATED and other parse outcomes by cell and model; response to the relevant edit (the answer is correct under the edited prompt) as the assay check.
5. Missing results (TRUNCATED, UNPARSEABLE, MULTIPLE_CANDIDATES, jobs not run) are NOT_EVALUATED and reported, never wrong and never zero.
No p-values; ten structures; descriptive. Any cue claim from this run is exploratory and needs the stated caveats of J14.8 to J14.12.
