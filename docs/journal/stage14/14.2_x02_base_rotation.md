### J14.2-002 · 2026-10-16T11:15 · observation
kind: observation
**What [V, algebra and property tests]:** A base-relative label has a structural property. With
`L_i` the four gold log-probabilities, the label under base `b` is `1[ max over j != b of (L_b - L_j) >= 0.5 ]`,
that is, variant `b` is at least 0.5 nats more likely than the least likely other variant.
- The lowest-likelihood variant used as the base can never be positive (no variant is lower), so **no family can
  be positive under all four bases**.
- A family is positive under at least one base exactly when `range >= 0.5`. So "base-dependent label" is the
  same set as "range >= 0.5"; its size (89% for Qwen) is structural, not a finding about instability.
- With a positive threshold, the clamp in the repo's form (J14.0-003) cannot change a label. The script asserts
  this for every row instead of assuming it.
**Consequence:** The informative quantities are different: how many legacy-negative families have range >= 0.5
(the label misses them when variant 0 is not one of the more likely renderings), how the positive count moves
with the base, and how the Qwen/Llama overlap moves with the definition. The summary file records the
identities explicitly (`structural_identities`) and carries interpretation notes so a reader does not mistake
them for results. The CM_B_UM_059 case is the plan's illustration of this: base 0 positive, base 1 negative on
identical values.

### J14.2-003 · 2026-10-16T11:20 · decision
kind: decision
**What:** `matches_reported` in `src/physmon/governance/recompute.py` now takes an explicit tolerance in units
of the last printed digit: 0.5 by default (a correctly rounded printing only) and 1.0 where a source may have
truncated. Only the plan-example check uses 1.0.
**Why:** The plan prints the base-1 value as -9.093 (B1.3, p.8) while the digest and the decision log say
-9.094. The exact value is -9.09375, a binary half-way case that rounds to -9.094 and truncates to -9.093; the
same applies to -55.5625 (plan -55.562, digest -55.563). A rounding-only check would reject one printing.
**Effect on Stage 14.1:** None. The 0.5-unit default accepts every rounding the earlier equality-after-rounding
rule accepted; all X01 tests still pass and no X01 outcome changes. The committed X01 attempt was produced
under the earlier rule and is not re-run.
**Tests [V]:** `tests/v2/test_recompute_v2.py` pins both behaviours. One test expectation I wrote for the median
absolute deviation was wrong by hand arithmetic (the correct value for the plan example is 0.734375); the code
was right and the test was corrected.
