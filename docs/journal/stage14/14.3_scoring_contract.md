### J14.3-001 · 2026-10-16T11:40 · observation
kind: observation
**What [V, code]:** What the Stage 6 behavioural runs scored. In `scripts/run_behavioural.py:519-535` the scored
string is `family_payload["correct_answer"]` (for example `6.928 N*m`), passed to
`physmon.models.logprob.compute_reference_answer_logprob`, which tokenizes the chat-templated prompt with
`add_special_tokens=True` and the answer separately with `add_special_tokens=False` and concatenates them
(`src/physmon/models/logprob.py:35-37`). The system prompt (`run_behavioural.py:41-46`) instructs the model to
return exactly `Answer: [value] [unit]`.
**Consequence:** The teacher-forced target omits the instructed `Answer:` prefix, so the scored first token is the
digit that the model would emit only after "Answer: ". Whether this dominates the large negative gold
log-probabilities (typically -25 to -55) cannot be decided without forward passes; it is the format-mismatch
threat H0-F (v2 §4.1, p.14).

### J14.3-003 · 2026-10-16T11:55 · decision
kind: decision
**What:** Freeze the scoring interface as code, not prose: `src/physmon/benchmark/scoring_contract.py`
(stdlib only). It defines (1) seven equal-meaning output wrappers (`plain`, `answer_line`, `boxed`, `json`,
`sentence`, `decimal_plain`, `scientific`), each with the instruction line that asks for exactly that format,
so the scored string is the string the model is told to emit; (2) a round-trip parser that proves the wrappers
carry the same number and unit; (3) the answer-span arithmetic for teacher-forced scoring; (4) a leading-special-
token counter; (5) a SHA-256 fingerprint of every frozen string so a later run can prove which contract it used.
**Why:** v2 P1.3 asks for "exact frozen wrappers" with exact tokenizer ids for every answer sequence (p.17),
and card X03 needs them before any GPU work (p.39). `answer_line` is asserted equal to the Stage 6 system prompt
so the existing records stay interpretable.
**Design choices:** all 140 committed answers are `<value> <unit>` strings, so the wrappers need no special
cases; `decimal_plain` and `scientific` are value-preserving rewrites (for example `1.124e6` to `1124000` and
`6.928e0`); a malformed answer raises and would be recorded NOT_EVALUATED, never guessed.
**Tests [V]:** `tests/v2/test_scoring_contract_v2.py` (9 tests): every committed answer round-trips through every
wrapper with the same value and unit; the `answer_line` instruction equals the Stage 6 system prompt exactly; the
fingerprint changes if a frozen string changes; the span arithmetic and the duplicate-token counter.

### J14.3-004 · 2026-10-16T12:05 · decision
kind: decision
**What:** The audit (`scripts/v2/s143_scoring_audit.py`) runs on all 1,120 committed Stage 6 records with the real
Qwen2.5-7B and Llama-3.1-8B tokenizers and checks seven contract clauses: S1 prompt bytes and answer equal the
rendered family JSON; S2 chat template with generation prompt; S3 no duplicated leading special token; S4 separate
equals joint tokenization (the span is exact); S5 the scored string equals the instructed format; S6 behavioural
and extraction token ids are identical; S7 the same boundary check for every wrapper. It also tests, per P1.4,
whether the 0.5-nat label is easier to cross for longer answers, and writes the cases for the manual
teacher-forced scoring that a later approved GPU job must run.
**Trust boundary:** tokenizers are loaded with `local_files_only=True` and `trust_remote_code=False`; the project
loader hardcodes `trust_remote_code=True` and is not used here. No model weights are opened.
**Tests [V]:** `tests/v2/test_scoring_audit_s143.py`. A hermetic test found a real edge case (an empty length
tercile when fewer than three families are present made `min()` fail); it was fixed before the run. The
end-to-end test is skipped when the model-store tokenizers are absent.

### J14.3-005 · 2026-10-16T12:15 · command

**What:** Dry run into the session scratchpad (not the repo) to inspect results before committing.
**Result [V] (all 1,120 records):**
- S1, S2, S4, S7 PASS. S3, S5, S6 FAIL.
- S3: every Llama behavioural prompt (560 of 560) starts with two BOS tokens (`[128000, 128000, ...]`): the chat

- S5: all 1,120 generations (both models) start with `Answer:`, while the scored string omits that prefix.

  expected for a sum. No evidence in these stored values that longer answers make the 0.5-nat label easier to
  cross (descriptive; families are not independent).

### J14.3-009 · 2026-10-16T12:40 · decision
kind: decision
**What:** Do not fix the scoring defects in the existing scripts in this stage.
**Why:** The legacy scripts produced committed records; changing them in place would break the link between a
record and the code that made it, and any job that reads them would see different code (skill: "do not edit
files a pending job reads"; no job is pending now, but the provenance argument holds). The contract instead
makes the rules explicit for new runs (rule 2: BOS exactly once; rule 4: identical sequences) and a later
stage implements a new scorer that obeys them. Whether and how to re-score Llama is a user decision.
**v2 reference:** P0.4 and §9.1 CI checks "correct target span IDs" (p.16, p.43); never patch new experiments
onto a broken denominator (p.16).
