### J14.0-003 · 2026-10-16T08:36 · observation
kind: observation
**What [V]:** The repo's legacy `S_lp` and the plan's base-rotation formula are not the same
expression.
- Repo (`src/physmon/formal/sensitivity.py:187-195`, `scripts/analyse_stage4.py:258-275`):
  `S_lp = max over ALL variants j of (L_base - L_j)`, which includes `j = base` and therefore can never
  be negative (the base contributes 0).
- Plan (B1.3 p.8, P1.1 p.17): `max over j != base of (L_base - L_j)`, which can be negative. The plan's
  "+10.031 at base 0, -9.094 at base 1" for CM_B_UM_059 uses this form.
**Why it matters:** For Stage 14.2 (X02) the "legacy label under a different base" depends on which
form is meant. Under the repo's implementation the base-1 score for CM_B_UM_059 would be clamped at
0, not -9.094; under either form the 0.5-nat label still flips between base 0 and base 1.
**Decision:** X02 will compute and report both forms side by side and name them explicitly
(`legacy_repo_clamped`, `legacy_plan_signed`). It will not choose one silently.
**v2 reference:** B1.2-B1.3 (p.6-8); P1.1 (p.17); card X02 (p.39).
